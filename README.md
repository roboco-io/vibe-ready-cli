# vibe-ready-cli

`vibe-ready-cli`는 리포지토리가 바이브 코딩을 시작하기에 얼마나 준비되어 있는지 판독하는 CLI 도구입니다. 감으로 판단하지 않고, 리포지토리 안의 구조와 검증 체계를 실제로 살펴본 뒤 준비 상태와 개선 포인트를 알려주는 것을 목표로 합니다.

## 무엇을 판독하나

다음 항목을 근거로 준비도를 평가합니다.

- 리포지토리 구조
- 테스트 존재 여부와 커버리지 수준
- 문서화 상태
- CI/CD 설정
- 훅 기반 검증 체계
  - `lint`, unit test, integration test, e2e, spec 검증
- 바이브 코딩 설정
  - `AGENTS.md`, `CLAUDE.md`
  - 훅, 스킬, 에이전트 설정

## 왜 필요한가

바이브 코딩은 시작 속도보다 기반 품질에 더 크게 영향을 받습니다. 이 도구는 "바로 작업해도 되는 리포지토리인지", "무엇이 빠져 있는지", "어떤 순서로 보강해야 하는지"를 빠르게 보여주기 위한 판독기입니다.

## 현재 상태

이 저장소는 아직 구현 전 단계입니다. 현재는 아이디어와 방향을 정리한 문서가 중심입니다.

- [`docs/ideation.md`](docs/ideation.md): 제품 아이디어와 평가 항목 정리
- [`AGENTS.md`](AGENTS.md): 이 저장소 작업 가이드
- [`CLAUDE.md`](CLAUDE.md): 에이전트 작업 맥락 정리

`.omc/`, `.omx/` 같은 로컬 상태 디렉터리는 개발 도구가 생성한 작업 파일이며, 제품 소스 디렉터리로 취급하지 않습니다.

## 예정 인터페이스

아직 CLI 엔트리포인트는 구현되지 않았지만, 목표 인터페이스는 아래와 같습니다.

```bash
vibe-ready /path/to/repository
```

예상 출력은 다음을 포함합니다.

- 전체 준비 상태 요약
- 체크 항목별 pass/fail
- 근거가 있는 판정 이유
- 우선순위가 있는 개선 액션 아이템

## 구현 원칙

- 각 체크는 한 가지 책임만 갖도록 분리합니다.
- "점수"보다 "근거"를 우선합니다.
- 새 체크를 추가할 때는 대응 테스트와 fixture를 함께 추가합니다.
- 명령어 표면은 단순하게 유지하고, 내부 체크는 모듈식으로 확장합니다.
