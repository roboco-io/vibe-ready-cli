# Chapter 4: Harness Engineering

> **Time required**: ~15 minutes
> **Key Insight**: Creating code is only half the battle — making it easy for AI agents to work with that code is equally important.

## Context

The MVP is working. But there's an irony: **this tool measures vibe coding readiness, so what is its own vibe coding readiness score?**

The initial CLAUDE.md generated by `/init` contained only the bare minimum. Now that the actual implementation is complete, it's time to apply **harness engineering** so agents can effectively understand and work with this project.

## The Prompt

```
Set up harness engineering configuration so agents can work well with the current project.
```

## What Happened

### 1. Strengthening CLAUDE.md

Initial CLAUDE.md (20 lines, overview only):

```markdown
## Project Overview
**vibe-ready-cli** is a CLI reader that analyzes how ready a repository is for vibe coding.

## Status
Early project stage (ideation). No implementation code yet.
```

CLAUDE.md after strengthening (105 lines, complete guide):

```markdown
## Tech Stack
- Runtime: Node.js >= 18, TypeScript (ES2022, ESM)
- Analysis engine: @anthropic-ai/claude-agent-sdk
- CLI: commander, chalk
- Testing: vitest

## Build & Development Commands
npm install / npm run build / npm test / npm run test:watch

## Architecture
src/
  index.ts      # CLI entry point
  analyzer.ts   # Repo analysis via Claude Agent SDK
  scorer.ts     # Weighted average score + grade + penalty calculation
  reporter.ts   # Terminal report output
  types.ts      # Type definitions, scoring model
  prompts/
    analyze.ts  # LLM analysis prompt builder

## Data Flow
CLI args → index.ts → analyzer.ts → scorer.ts → reporter.ts → terminal output

## Scoring Rules
- Each category: 0–100 points, grade A/B/C/D/F
- Penalty: mandatory category F → overall grade capped at C

## Coding Conventions
- File names: kebab-case, 2 spaces, ESM (.js extension required)
```

**Before → After**: Agents can now understand the project's tech stack, build process, architecture, data flow, and coding conventions in a single turn.

### 2. Updating AGENTS.md

The initial AGENTS.md stated "no code yet." This was updated to reflect the current implementation:

- Module structure and the role of each file
- Core types (`LLMAnalysisOutput`, `AnalysisResult`, `CATEGORY_WEIGHTS`)
- Extension points (adding new categories, output formats, CI gate mode)
- Commit rules (Conventional Commits)

### 3. Creating `.claude/settings.json`

Configures agent permissions and automation hooks:

```json
{
  "permissions": {
    "allow": [
      "Read", "Glob", "Grep",
      "Bash(npm run build)",
      "Bash(npm test)",
      "Bash(npx tsx src/index.ts*)",
      "Bash(git *)"
    ]
  },
  "hooks": {
    "PreCommit": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "npm run build && npm test"
          }
        ]
      }
    ]
  }
}
```

**Key design decisions**:

| Setting | Reason |
|---------|--------|
| Auto-allow read tools | So agents aren't interrupted during exploration |
| Auto-allow build/test | To run the verification loop quickly |
| PreCommit hook | Prevents committing broken code — blocks commit if build fails |

## The 3 Layers of Harness Engineering

The harness engineering applied in this project forms a 3-layer structure:

```
┌─────────────────────────────────────────────┐
│  Layer 1: Context (CLAUDE.md)               │
│  "What is this project and how does it work"│
├─────────────────────────────────────────────┤
│  Layer 2: Guidelines (AGENTS.md)            │
│  "What rules should the agent follow"       │
├─────────────────────────────────────────────┤
│  Layer 3: Guardrails (.claude/settings.json)│
│  "What can and cannot the agent do"         │
└─────────────────────────────────────────────┘
```

- **Layer 1 (Context)**: Helps agents quickly understand the project
- **Layer 2 (Guidelines)**: Guides agents to work with consistent patterns
- **Layer 3 (Guardrails)**: Prevents agents from taking dangerous actions

## Lessons Learned

1. **The harness must evolve with the code**: The initial CLAUDE.md generated by `/init` is just a starting point. Every time implementation progresses, the harness must be updated alongside it.

2. **The PreCommit hook is your safety net**: Agents can sometimes attempt to commit code with a broken build. Enforcing `npm run build && npm test` as a PreCommit hook prevents this.

3. **Permissions follow the principle of least privilege**: Only grant the agent the tools it needs (Read, Glob, Grep, build/test) automatically; require user confirmation for everything else.

4. **Data flow is the most important documentation**: When explaining architecture to an agent, showing **how data flows** is more effective than a class diagram.
